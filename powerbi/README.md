# Power BI Dashboard Build Guide

## Purpose

Power BI consumes only curated Snowflake MART tables from this project. Do not connect reports directly to RAW, STAGING, or CORE tables.

## Step 1 — Create Reporting Views

Run:

```bash
snowsql -f sql/14_powerbi_views.sql
```

## Step 2 — Connect Power BI to Snowflake

Connect to these views:

```text
DIVVY_DB.MART.VW_POWERBI_OPERATIONS
DIVVY_DB.MART.VW_POWERBI_STATION
DIVVY_DB.MART.VW_POWERBI_RIDER
DIVVY_DB.MART.VW_POWERBI_FLEET
```

Recommended mode:

```text
Import
```

Import mode is simplest for a portfolio project and keeps report interactions fast.

## Step 3 — Apply Theme

In Power BI Desktop:

```text
View → Browse for themes → powerbi/theme.json
```

## Step 4 — Add Measures

Create a measure table named:

```text
_Measures
```

Add the measures from:

```text
powerbi/measures.dax
```

## Step 5 — Build Pages

### 1. Mobility Overview

Primary table: `VW_POWERBI_OPERATIONS`

Recommended visuals:

- KPI cards for total trips, member trips, casual trips, average trip duration, active stations, and available vehicles
- Line chart for daily total trips by `REPORT_DATE`
- Stacked column chart for member versus casual trips
- Line chart for average trip duration by date

### 2. Station Intelligence

Primary table: `VW_POWERBI_STATION`

Recommended visuals:

- Top stations by `TOTAL_STATION_TRIPS`
- Bar chart for origin versus destination trip counts
- Table with station id, station name, trips, average vehicles available, and average docks available
- Station utilization ranking by date

### 3. Rider Analytics

Primary table: `VW_POWERBI_RIDER`

Recommended visuals:

- Rider mix by `RIDER_TYPE`
- Daily trips by rider type
- Average duration by rider type
- Unique start and end station counts by rider type

### 4. Fleet Snapshot

Primary table: `VW_POWERBI_FLEET`

Recommended visuals:

- Vehicle count by `VEHICLE_TYPE_ID`
- Vehicle count by `VEHICLE_STATUS`
- Active vehicle count by date
- Latest snapshot timestamp card

## Layout Guidance

Use a clean four-page report:

```text
Page 1: Mobility Overview
Page 2: Station Intelligence
Page 3: Rider Analytics
Page 4: Fleet Snapshot
```

Keep slicers consistent:

- `REPORT_DATE`
- `RIDER_TYPE`
- `STATION_NAME`
- `VEHICLE_TYPE_ID`
- `VEHICLE_STATUS`

## Validation Before Publishing

Confirm these Snowflake checks before publishing the report:

```sql
SELECT COUNT(*) FROM DIVVY_DB.MART.MART_OPERATIONS;
SELECT COUNT(*) FROM DIVVY_DB.MART.MART_STATION;
SELECT COUNT(*) FROM DIVVY_DB.MART.MART_RIDER;
SELECT COUNT(*) FROM DIVVY_DB.MART.MART_FLEET;

SELECT
    (SELECT COUNT(*) FROM DIVVY_DB.CORE.FACT_TRIP) AS FACT_TRIP_COUNT,
    (SELECT COALESCE(SUM(TOTAL_TRIPS), 0) FROM DIVVY_DB.MART.MART_OPERATIONS) AS MART_TOTAL_TRIPS;
```

Expected result: `FACT_TRIP_COUNT` and `MART_TOTAL_TRIPS` should match.

## Step 6 — Save the PBIX

Save the file as:

```text
Urban_Mobility_Fleet_Intelligence.pbix
```

Suggested location:

```text
powerbi/Urban_Mobility_Fleet_Intelligence.pbix
```

Do not commit large `.pbix` files to GitHub unless you intentionally want the binary report stored in the repo.

## Refresh Notes

- Historical data is loaded through `sql/08_historical_ingestion.sql`.
- GBFS snapshots are generated by Python, uploaded to ADLS, loaded through Snowpipe, and processed by `SP_PROCESS_GBFS_STREAM`.
- Power BI should refresh after Snowflake MART tables are refreshed.
